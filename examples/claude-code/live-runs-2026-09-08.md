# Three real runs through Claude Code (2026-09-08)

These are condensed transcripts of a fresh `claude -p` session talking to `linkedin-toolkit-mcp` over Streamable HTTP,
against a real signed-in LinkedIn session, in Copilot mode. Names are public LinkedIn profiles as returned by search.
Config used (`.mcp.json` in the working folder):

```json
{ "mcpServers": { "linkedin-toolkit": { "type": "http", "url": "http://127.0.0.1:47830/mcp",
  "headers": { "Authorization": "Bearer <token from lit config get token --reveal>" } } } }
```

## 1. Mandate → shortlist → queued invites

Prompt: *"Mandate: a Series B fintech in London needs a CTO with payments experience. Search 10 people, create a list,
pick the 3 strongest, queue a personalised invite to each, report the queue ids."*

Tools called: `linkedin_search_people` (1), `linkedin_list_create`, `linkedin_list_add`, `linkedin_send_invite` (3), `linkedin_queue_list`.

Result: 10 real profiles (search total 150), list `Mandate: Fintech CTO London`, a shortlist table with one-line reasons,
three two-sentence notes each referencing something from the person's headline, and three queue ids in `pending`.
Invite quota untouched (0/20) because Copilot held them. The popup's Queue tab showed the three cards with editable notes
and Approve / Reject. Nothing was sent.

## 2. CSV of names → LinkedIn profiles (Research Pack)

Prompt: *"Read names.csv (name, company), resolve each person, run a research pack, report URL, headline, confidence, signals."*

Tools called: `linkedin_research_resolve`, `linkedin_research_pack`, `linkedin_research_get`.

Result on the first run: one of three rows resolved correctly (Reid Hoffman → /in/reidhoffman, confidence 1.0); two rows
fell back to a company match. That exposed a resolver ordering bug (company fallback preferred over a strong person
name match) which was fixed the same evening; see `docs/voyager-endpoints.md` for the endpoint status of the day.

## 3. Company → employee list

Prompt: *"A user dropped https://www.linkedin.com/company/monzo-bank/ . Look it up, fetch 20 employees over two pages,
put them in a list."*

Tools called: `linkedin_get_company`, `linkedin_get_company_employees` (2), `linkedin_list_create`, `linkedin_list_add`.

Result: 20 real employees with headline and location, list `Monzo — employees sample` with 20 added / 0 duplicates.
The agent also flagged two rows as agency recruiters rather than staff, from their headlines. The company card came back
thin on that run (GraphQL decoration), which is why company lookup now uses the REST decoration.

## What these runs proved

- An agent can go from a one-line brief to a reviewed, human-gated outreach queue with real data and no browser automation.
- Every write stopped at the queue. The person at the keyboard decides.
- Endpoint drift is visible and fixable: `lit endpoints check` tells you which calls are healthy before you start.
