# Recording the demo GIF

The GIF is the single highest-leverage asset in the repo. Most people who land on the README will
watch it and decide, and never read a word below it. Budget an afternoon.

**Target:** `docs/assets/demo.gif` — 30 seconds, ≤ 8 MB, 1200 px wide, readable at half size.

Until it exists the README shows `docs/assets/demo-storyboard.png`, generated by the Pillow script
in the launch notes. Replace the image reference in the README when the GIF lands.

## What it must show, in order

The whole argument in four beats. Do not add a fifth.

| Beat | Seconds | Shows |
|---|---|---|
| **1. Ask** | 0–5 | One sentence typed into an agent. Plain English, no jargon. |
| **2. Search** | 5–15 | Tool calls scrolling, typed JSON coming back, counts going up. Speed is the point — this is what "3 tool calls instead of 300 screenshots" looks like. |
| **3. Draft** | 15–22 | Real invite notes with a real hook, character counts under 300, and the word **queued** rather than sent. |
| **4. Approve** | 22–30 | Cut to the extension popup's Queue tab. A human clicks approve on three, rejects one. End on "3 approved · sent at human pace". |

Beat 4 is not optional. The approval queue is the thing that separates this from every other
LinkedIn automation demo, and it is the thing a sceptical reader is looking for.

## Setup

**Use a throwaway LinkedIn account.** Never Dominic's. Never anyone's real network.

Or, better, record against the fake extension client — it produces real envelopes, real error
codes and synthetic people, and nothing touches LinkedIn:

```bash
lit serve --http --fake
```

Seed it so the results look plausible: real-sounding names, real-sounding companies, a mix of
seniorities. A demo full of "Test User 1" reads as vapourware.

**Terminal:** 1200 × 700, dark theme, 15–16 pt font. Cursor visible. No personal paths, no other
tabs, no notification bar, no Slack popping up mid-take.

**Chrome:** a clean profile with only this extension. Bookmarks bar off. Popup zoomed so the queue
rows are legible at half size.

## The script

Type this, exactly. It is 96 characters and it fits on one line at 16 pt:

```
Find 20 heads of data engineering at Series B fintechs in London and draft invites for the top 8
```

Then let it run. Do not narrate, do not cut to a face, do not add music.

Timings that make it watchable:

- **Type the prompt at human speed.** Roughly 3 seconds. Do not paste — a paste reads as fake.
- **Let tool calls stream.** If the run genuinely takes 90 seconds, speed that section to 4× rather
  than cutting it. Seeing the calls go past is the proof.
- **Hold on the first drafted note for 2 full seconds.** People need time to read it and notice it
  says something specific rather than "I was impressed by your profile".
- **Hold on `8 × queued, 0 sent` for 1.5 seconds.** This is the money frame.
- **The popup cut should be a hard cut**, no transition. New context, new window.
- **Hold the final frame for 2 seconds** so the loop does not feel frantic.

## Tools

**macOS**

```bash
brew install gifski
# Record with QuickTime (File → New Screen Recording), then:
ffmpeg -i demo.mov -vf "fps=12,scale=1200:-1:flags=lanczos" -f yuv4mpegpipe - \
  | gifski -o docs/assets/demo.gif --fps 12 --quality 80 -
```

Or [Kap](https://getkap.co) — records straight to GIF with a size target, and is the fastest route
if you are not fussy.

**Windows**

[ScreenToGif](https://www.screentogif.com) does record, edit and export in one app, including
frame-by-frame deletion, which is the feature you will actually want. Export: 12 fps, 1200 px wide,
lossy quality ~75.

**Linux**

[Peek](https://github.com/phw/peek) for simple recordings; `ffmpeg` + `gifski` as above for
control.

**Any platform, if the GIF will not get under 8 MB:** ship an MP4 instead. GitHub renders `.mp4`
inline in a README and it will be a quarter of the size at better quality. The only cost is that
it does not autoplay in every context.

## Getting it under 8 MB

In order of what to try:

1. **Cut seconds.** 30 → 24 is a 20% saving and nobody notices.
2. **12 fps, not 24.** Terminal text at 12 fps is fine; nothing moves smoothly anyway.
3. **1200 px wide, not 1600.** The README column is narrower than that regardless.
4. **`gifski --quality 75`.** Below about 70 the text starts to shimmer.
5. **Crop.** Nothing outside the terminal or the popup needs to be in frame.
6. **Fewer colours** — `--extra` in gifski, or `ffmpeg` palettegen with `max_colors=128`. A dark
   terminal has very few colours to begin with.

Check: `ls -lh docs/assets/demo.gif`, then view it in the rendered README on GitHub, not locally.

## Do not

- Do not show a real person's profile, name, photo, or headline. Synthetic or throwaway only.
- Do not show the LinkedIn logo prominently, or anything that reads as LinkedIn branding.
- Do not show a message actually sending. The demo ends at approval, deliberately — that is the
  honest depiction and it is also the better story.
- Do not add background music, a talking head, or a title card. The terminal is the content.
- Do not speed up the approval beat. Everything else can be 4×; that one is the point.
